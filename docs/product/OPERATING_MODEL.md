# Operating Model

## Daily cycle

### 1. Capture
The system receives or creates operational items:
- referral;
- callback;
- cancellation;
- task;
- handover;
- waste event;
- recurring-cost review;
- capacity gap.

### 2. Assign
Every actionable item receives:
- owner;
- priority;
- next action;
- due date/time;
- value-at-risk estimate when applicable.

### 3. Work
Staff process their queue rather than relying on memory, paper notes or informal messages.

### 4. Escalate
The system changes state as risk increases:
- Green;
- Amber/Yellow;
- Red;
- Recovery.

Escalation is based on configurable rules, not hidden logic.

### 5. Resolve
The item can only be closed when:
- the required outcome is recorded; or
- a valid closure reason is selected.

### 6. Measure
Revenue recovered, cost avoided or staff time saved is calculated.

### 7. Verify
An authorised person reviews significant savings and supporting evidence.

### 8. Learn
Repeated events are grouped into systemic patterns.

### 9. Prevent
A corrective action is implemented and compared against the prior baseline.

---

# Example: lost-referral prevention

Referral received → owner assigned → first-contact deadline → first attempt → second attempt if needed → waiting/booking/decline outcome → overdue alert if untouched → escalation → outcome captured → value recovered measured.

# Example: wasted staff time

Staff records repeated manual task → time estimate collected → recurring pattern identified → root cause confirmed → automation/process change approved → intervention implemented → staff time measured again → verified hours saved recorded.

# Example: cancellation recovery

Cancellation received → vacancy created → matching waitlist candidate list → contact attempts → replacement booking → recovered revenue recorded → verification.

---

# Business rules

1. No material work item may exist without ownership.
2. Ownership transfer is not complete until accepted.
3. An overdue item cannot become Green without an action.
4. Closed items remain in history.
5. A saving must have a baseline.
6. A saving cannot be Verified without evidence.
7. A single event cannot be counted in more than one savings category unless allocation rules explicitly prevent double-counting.
8. Management reporting uses operational data and avoids clinical detail.
